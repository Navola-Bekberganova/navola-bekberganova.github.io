# Navola Bekberganova — Academic & Professional Portfolio

A static, multi-page portfolio website (HTML5, CSS3, vanilla JavaScript — no build step, no framework).

## Run locally

Any static file server works. From this folder:

```bash
python -m http.server 8000
```

Then open <http://localhost:8000>. You can also double-click `index.html`; everything works from the file system, but a local server is closer to how the live site behaves.

## Updating content

**All content is edited in `assets/js/data.js`.** The header, navigation and footer are generated by `main.js`, so a change made once appears on every page.

### Placeholders

- `null`, `""` or `[]` → a clearly marked *"… — to be added"* placeholder is shown.
- `undefined` (or leaving the field out) → the field is hidden.
- **Before you publish**, set `settings.showPlaceholders: false` at the top of `data.js`. All placeholders and empty document slots are then hidden.

### Add a document (PDF) to anything

1. Copy the PDF into the matching folder, e.g. `assets/documents/experiences/iom-project-report.pdf`.
2. In `data.js`, find the entry and set its `file`:

```js
documents: [
  { title: "Project report", file: "assets/documents/experiences/iom-project-report.pdf" },
  { title: "Workshop summary", file: "assets/documents/experiences/iom-workshop-summary.pdf" },
],
```

Each experience, project, education entry, certificate, language and publication can have any number of documents. External links use `links: [{ label: "Institution page", url: "https://..." }]`.

Use file names without spaces (e.g. `oxford-certificate.pdf`).

### Add a new experience

Copy an existing object in the `experience` array and edit it. Entries are shown in array order, so put the newest first. Set `featured: true` to also show it on the home page.

```js
{
  id: "unique-id",                  // used for links such as experience.html#unique-id
  role: "Research Assistant",
  organization: "University …",
  team: "Research group (optional)",
  location: "City, Country",
  start: "Jan 2027",
  end: "Present",
  summary: "One-sentence summary.",
  responsibilities: ["…", "…"],
  objectives: ["…"],                // optional
  methods: ["…"],                   // optional
  contributions: ["…"],             // optional
  tags: ["…"],
  documents: [{ title: "Internship report", file: null }],
  links: [],
},
```

### Add a project

Add an object to `projects`. Fields: `id`, `title`, `category` (filter buttons are created automatically from the categories), `organization`, `period`, `overview`, `problem`, `objectives`, `methodology`, `tools`, `results`, `image` (e.g. `assets/images/projects/my-project.jpg`), `github`, `links`, `documents`.

### Add a certificate, award or scholarship

Add an object to `certificates` with a `category` of `programme`, `course`, `award` or `achievement` (categories are defined in `certificateCategories`):

```js
{
  category: "course",
  title: "Course title",
  issuer: "Issuing institution",
  date: "Mar 2027",
  description: "Short description.",
  documents: [{ title: "Certificate", file: "assets/documents/certificates/course.pdf" }],
  verifyUrl: "https://verify.example.org/…",
},
```

### Add a publication

Follow the commented template above `publications: []` in `data.js`. The empty-state message disappears automatically once an entry exists. Supports title, authors, venue, date, abstract, DOI/URL, PDFs and an optional BibTeX block with a copy button.

### Change the profile photo or CV

- Photo: save as `assets/images/profile.jpg` (portrait, about 800×1000 px) and set `profile.photo` in `data.js`.
- CV: replace `assets/documents/cv/Navola_Bekberganova_CV.pdf` (keep the name, or update `profile.cv`).

### Contact and academic profiles

Edit `contact` in `data.js`. Fill in `url` for ORCID, Google Scholar or ResearchGate to show them; add more entries in the same format (available icons: `linkedin`, `orcid`, `scholar`, `researchgate`, `github`). The phone number is hidden unless you set `phone.public: true`.

## Deploy to GitHub Pages

The site is plain static files with relative paths, so it works both as a **project site** (`https://USERNAME.github.io/REPO-NAME/`) and a **user site** (`https://USERNAME.github.io/`). No build step, backend or database is involved.

### Option A — upload through the browser (no Git needed)

1. Sign in to GitHub and click **New repository**.
   - For `https://USERNAME.github.io/` name it exactly `USERNAME.github.io`.
   - Otherwise any name works, e.g. `portfolio` → `https://USERNAME.github.io/portfolio/`.
2. Make it **Public** (GitHub Pages on private repos requires a paid plan) and create it.
3. Click **Add file → Upload files** and drag in the **contents** of this folder: `index.html` and the other `.html` files, `404.html`, `assets/`, `README.md`, `.nojekyll`.
   - Upload the files *inside* the folder, not the folder itself, so `index.html` sits at the top level of the repository.
   - `.nojekyll` is a hidden file. If your file browser hides it, create it on GitHub instead: **Add file → Create new file**, name it `.nojekyll`, leave it empty, and commit.
   - Do **not** upload the original CV with spaces in its name (`2026_05_CV_Navola___int_officer (3).pdf`); the published copy is in `assets/documents/cv/`.
4. Click **Commit changes**.
5. Go to **Settings → Pages**. Under *Build and deployment*, set **Source: Deploy from a branch**, **Branch: `main`**, folder **`/ (root)`**, and click **Save**.
6. After a minute or two, the address appears at the top of the Pages settings. Open it.

### Option B — with Git

```bash
cd "path/to/Navola website"
git init
git add .
git commit -m "Initial portfolio"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO-NAME.git
git push -u origin main
```

Then enable Pages as in step 5 above. The included `.gitignore` keeps the original CV file (with spaces in its name) out of the repository.

### Updating the live site

Edit files (usually only `assets/js/data.js` and new PDFs), then upload or push them again. GitHub Pages redeploys automatically within a minute or two. If you don't see the change, force-refresh the browser (Ctrl+F5 / Cmd+Shift+R).

### Things that matter on GitHub Pages

- **File names are case-sensitive.** `Report.pdf` and `report.pdf` are different files online, even though Windows treats them as the same. Paths in `data.js` must match the file name exactly. Use lowercase names without spaces, e.g. `iom-project-report.pdf`.
- **Keep paths relative.** Write `assets/documents/...`, never `/assets/documents/...` or `C:\...`. A leading `/` breaks project sites served under `/REPO-NAME/`.
- **`.nojekyll`** tells GitHub to serve the files as they are, without the Jekyll processor. Keep it in the repository root.
- **`404.html`** is shown for any missing URL. It finds the site root automatically on `*.github.io` project sites. If you use a **user site** (`USERNAME.github.io` repository) or a **custom domain**, open `404.html` and set `var SITE_ROOT = "/";`.
- **File size:** GitHub rejects files over 100 MB, and the browser uploader accepts files up to 25 MB each. Compress large PDFs before uploading. Pages sites should stay under 1 GB in total.
- **Everything in the repository is public**, including every PDF in `assets/documents/`. Only upload documents you are happy to share.

### Custom domain (optional)

In **Settings → Pages → Custom domain**, enter your domain and follow GitHub's DNS instructions, then tick **Enforce HTTPS**. Remember to set `SITE_ROOT = "/"` in `404.html`.

### After the first deployment

- Open each page from the navigation and click a few document links to confirm they load.
- Add an absolute `og:image` URL in each page's `<head>`, e.g. `https://USERNAME.github.io/REPO-NAME/assets/images/og-image.jpg`, so links shared on LinkedIn show a preview image.

### Other hosts

The same folder also works unchanged on Netlify, Cloudflare Pages or a university web space: upload it as-is.

## Privacy rules for documents

Keep original, private documents outside `assets/`. If you store them in this project, put them in a folder named `all docs/` or in the project root: both are excluded by `.gitignore` and never uploaded. Only vetted copies in `assets/documents/` are published.

Before adding any new document to `assets/documents/`, open it and check that it does **not** contain:

- a date or place of birth, national ID / personal code, passport or student number
- an ID-style photo
- grades or transcripts
- recommendation or reference letters, or evaluation forms

If a document fails this check, describe it in `data.js` without a file (e.g. "Certificate available on request").

## Research page images

Cover illustrations live in `assets/images/projects/` (SVG, about 2–3 KB each) and are set per project with `image:` in `data.js`. Any JPG/PNG/SVG works; a 16:7 landscape ratio (e.g. 1200×525) fits the cards without cropping.

## Links to universities and organisations

Institution and organisation names on the site link automatically to their official websites. The addresses are listed once, in `organizations` near the top of `assets/js/data.js`:

```js
organizations: {
  "University of Glasgow": "https://www.gla.ac.uk/",
  // add more: "Exact name as written in data.js": "https://..."
},
```

The name must match the text exactly (e.g. the `institution`, `organization` or `issuer` field). Every place that name appears becomes a link.
